
## 1. 数据集结构

手写数字识别中，数据集 = 图片 + 标签（数字）。  
在 VLN 里，数据集 = **一条条自然语言导航指令 + 一段真实路径（ground truth path）+ 初始位置 + 3D 场景信息**。

### 具体对应关系：

| MNIST 数据集 | VLN 数据集（R2R/REVERIE） |
|-------------|---------------------------|
| 一张图片 | 一条指令文本，例如 “Walk into the kitchen and stop in front of the refrigerator.” |
| 标签（数字 3） | 真实路径（一系列视角点 ID），例如 `[vp1, vp5, vp9, vp12]` |
| 数据集划分：训练集/验证集/测试集 | 同样有 `val_unseen` 等划分，但这里只用了 **验证集** |

在代码 `R2RNavBatch`（`env.py`）里，数据集被加载成 `self.data` 列表，每一项包含 `instr_id`、`instruction`、`scan`（场景 ID）、`path`（真实路径）、`heading`（初始朝向）等字段。  
这个列表就是你熟悉的“所有测试样本”。

## 2. epoch 是什么？

在 MNIST 里，一个 epoch = 把所有训练样本完整过一遍。  
在这里，由于没有训练，一个 epoch 可以理解为 **把验证集中的所有指令都执行一遍**。

代码中的控制逻辑在 `agent_base.py` 的 `test()` 方法里：

- 如果 `iters` 参数为 `None`，就会进入 `while True` 循环，不断调用 `self.rollout()` 获取新的指令，直到每一条指令都被处理过一次——**这就相当于一个 epoch**。
- 如果 `iters` 设为一个数字（例如 10），那么只会处理 `iters` 次 `rollout`，即只跑一部分指令，**相当于只跑了测试集的若干个样本**。

当前 `parser.py` 里默认 `--iters 10`，所以**默认不是跑完整 epoch，而是只跑 10 条指令**。注释中也保留了 `# --iters None` 的写法，跑完整 epoch 时才会启用。

## 3. batch 是什么？

MNIST 里的 batch = 每次喂给模型的一组图片，用于计算一次梯度更新。  
这里 **没有训练，因此也没有“梯度更新”意义上的 batch**。但是，环境（`EnvBatch`）支持同时维护多个模拟器实例，这样可以一次并行处理多条指令，提高效率。

### 这个 `batch_size` 的实质：

- `batch_size` 参数（默认为 1）决定了一次 `rollout()` 会处理 **几条指令**。
- 在 `R2RNavBatch.reset()` 中，会从数据集里取出 `batch_size` 条指令，在每个对应的模拟器里初始化环境。
- `rollout()` 返回的 `traj` 列表长度就等于 `batch_size`，即**一次 rollout 得到 batch_size 条轨迹**。

你可以把它类比为：测试阶段每次取 `batch_size` 张图片进行计算，但这里的“计算”是在模拟器里一步步导航，最后才输出结果。

当前默认 `batch_size=1`，就是**每次只处理一条指令，走完一条导航路径**。

---

## 4. max_iterations 是什么？

1条指令会产生1条轨迹，1条轨迹最多max_iterations步
（默认10）

## 4. 运行流程（以一次完整的验证 epoch\iter 为例）

下面用一张简单的流程图来表示，同时和 MNIST 的过程进行对照。

### MNIST 测试流程（你已熟悉）
```
遍历测试集:
  for batch in test_loader:
    images, labels = batch
    outputs = model(images)
    loss = criterion(outputs, labels)
    计算准确率等指标
```
### VLN 项目的运行流程（对应关系）

1. **加载数据集**  
   `build_dataset` 从 JSON 里读入所有验证指令，得到一个 `R2RNavBatch` 对象。  
   **相当于** `test_dataset = MNIST(...)`。

2. **初始化 agent**  
   创建 `NavAgent`，这个 agent 持有一个大语言模型（比如 GPT-3.5）作为“大脑”。  
   **相当于** 加载一个训练好的 MNIST 模型。

3. **开始测试（验证）**  
   调用 `agent.test(iters=None)`，内部循环获取指令并执行：
   - `self.env.reset()`：取出一条（或 `batch_size` 条）指令，在 3D 模拟器里设置好起点位置。这时的观测包含当前视角的图像特征（文本化描述）和候选移动目标。  
     **相当于** 从测试集取出 `batch_size` 个样本。
   - `self.rollout()`：agent 根据指令和当前观测，让 LLM 决定下一步去哪个视角点，环境执行移动，得到新观测，反复执行直到 LLM 输出“Final Answer”或达到最大步数。  
     **相当于** 模型进行一次完整的前向推理，但这里是多步的序列决策过程。
   - 收集路径（`traj`），记录在 `self.results` 中。  
     **相当于** 保存模型对每个样本的预测标签。
4. **评价指标**  
   所有指令运行完后，`env.eval_metrics(preds)` 根据预测路径和真实路径计算成功率（SR）、路径长度加权成功率（SPL）、动态时间规整（nDTW）等指标。  
   **相当于** 计算准确率、召回率等。

5. **输出结果**  
   预测轨迹和分数写入 `preds/` 和 `logs/` 下的 JSON 文件。

## 6. 关键术语对照表

| 手写数字识别 | 视觉语言导航（本项目） |
|-------------|------------------|
| 图片 | 一条带指令的导航任务 |
| 标签（数字） | 真实路径序列（viewpoints） |
| 模型 | LLM agent（NavAgent） |
| 前向推理一次 | 执行一整条指令的导航过程（多步决策） |
| 训练 epoch | 无（只有验证） |
| 测试 epoch | 遍历验证集中所有指令一次 |
| batch size | 一次 `rollout()` 同时处理的指令条数 |
| iters (如不为 None) | 只跑指定次数的 rollout，即测试集子集 |
| accuracy | Success Rate (SR), SPL, nDTW等 |

## 7. 补充一个具体例子

假设 `batch_size=1`，`iters=5`，则运行过程为：
- 循环 5 次，每次从数据集中取 **1 条** 新指令（共 5 条不同的指令）。
- 对每条指令，agent 在 3D 环境里从起点出发，根据 LLM 的每次决策执行 1 步，直到认为到达目的地。
- 最终得到 5 条预测路径，与这 5 条指令的真实路径比较，计算平均指标。

这就完全对应：从 MNIST 测试集中取出 5 张图片，模型分别预测数字，然后看这 5 张的准确率。
