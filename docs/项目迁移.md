# RL-NavGPT 租用 GPU 服务器迁移指南

本文档用于将当前实验室服务器上的 RL-NavGPT 训练环境迁移到
租用 GPU 服务器。当前项目不是“一个 Docker 容器里包含所有东西”，
而是由三部分组成：

1. Docker 镜像中的 Ubuntu、CUDA、PyTorch、EGL 和系统依赖；
2. 宿主机 `/home/xl/lsl/RL-NavGPT` 挂载到容器
   `/workspace/RL-NavGPT`，其中包含代码、模型、R2R 数据、缓存和训练输出；
3. 宿主机 `/home/xl/lsl/rl-navgpt-container-home` 挂载到容器
   `/home/xl`，其中包含 `navgpt-rl`/`qwen-tf448` 虚拟环境和
   MatterSim 源码/编译产物。

Docker 的确可以迁移，但不能只传容器镜像。`docker commit` 不会把
bind mount 或 volume 里的数据写入镜像，因此代码、模型、数据集和
`/home/xl` 环境必须单独传输。

## 1. 推荐方案

当前项目推荐使用以下方案：

```text
旧服务器
  ├─当前容器 root filesystem
  │    └─ docker commit -> docker save -> 新服务器 docker load
  ├─RL-NavGPT
  │    ├─代码：Git clone/checkout
  │    ├─models：rsync
  │    ├─datasets/R2R：rsync
  │    └─需要保留的 outputs/checkpoint：rsync
  └─rl-navgpt-container-home
       └─rsync -> 新服务器，继续挂载到 /home/xl
```

这种方案有三个优点：

- 保留已经验证过的 PyTorch 2.7.1 + CUDA 12.8 + Python 3.11 环境；
- 保留 `/home/xl/venvs/navgpt-rl` 和已经安装好的 TRL/PEFT；
- 不把 30 GB Qwen 权重、CLIP 权重和数据集重复打包进 Docker
  镜像，后续更换代码或 checkpoint 也更方便。

## 2. 租卡前的硬件与平台要求

### 2.1 GPU 数量

当前主实验固定 `num_generations=4`，代码要求 GPU 数量能整除 4，
因此不改实验定义时支持：

| GPU 数量 | 模式 | 每张卡顺序生成的 rollout 数 | 建议 |
|---:|---|---:|---|
| 1 | single | 4 | 可运行，但最慢 |
| 2 | DDP | 2 | 性价比折中 |
| 4 | DDP | 1 | 推荐的主实验配置 |

不建议租 3 张卡后仍使用 `num_generations=4`，该组合会在启动前被代码
拒绝。当前启动器是单机 DDP（`torchrun --standalone`），因此 2/4 张卡必须
属于同一台租用主机，不能租多台独立单卡实例直接拼成当前 DDP。

### 2.2 GPU 显存

正式配置会在每张 GPU 上加载一份完整的 Qwen2.5-14B BF16 冻结主干，
并在长轨迹反向传播时产生动态显存峰值。建议租用：

- A100/H100 80 GB，或显存更大的同类 GPU；
- 4 张卡尽量使用同一型号；
- 不要在未做真实 1-step smoke test 前直接租 24/32/48 GB 卡跑
  `MAX_COMPLETION_LENGTH=38912` 的正式配置。

### 2.3 系统要求

建议选择：

- Linux x86_64；
- 安装了 NVIDIA 驱动、Docker 和 NVIDIA Container Toolkit；
- 驱动能够运行当前 CUDA 12.8 容器；
- 提供可持久数据盘，关机或释放 GPU 实例时不会删除数据；
- 允许 `docker load`/`docker run --gpus all`，或允许从私有镜像仓库启动。

如果平台只提供已建好的 Notebook 容器，不给 Docker daemon 权限，
参考本文第 10 节的降级方案。

### 2.4 磁盘空间

不要根据估计盲目购买数据盘。先在旧服务器宿主机执行：

```bash
cd /home/xl/lsl

du -sh \
  RL-NavGPT/models/Qwen2.5-14B-Instruct-1M \
  RL-NavGPT/models/clip-vit-large-patch14 \
  RL-NavGPT/datasets/R2R \
  RL-NavGPT/datasets/Matterport3D \
  rl-navgpt-container-home \
  RL-NavGPT/outputs \
  2>/dev/null

docker image inspect rl-navgpt:pre-egl-20260807 \
  --format 'image_size_bytes={{.Size}}' 2>/dev/null || true
```

只训练时，按“Docker 镜像 + container-home + Qwen + CLIP + R2R +
checkpoint”的实际大小购买，并额外预留至少 100 GB 给 checkpoint、
评测快照和临时文件。如果还要携带原始 Matterport3D 并重建 CLIP
视觉缓存，再把 Matterport3D 实际占用加入。

## 3. 哪些文件必须迁移

### 3.1 正式训练必须迁移

| 类型 | 路径 | 原因 |
|---|---|---|
| 代码 | 整个 Git 工作树 | 训练、奖励、评测和 DDP 逻辑 |
| Policy/Planner 基础模型 | `models/Qwen2.5-14B-Instruct-1M/` | 冻结基础权重和 tokenizer；LoRA 不能单独运行 |
| CLIP 模型 | `models/clip-vit-large-patch14/` | 训练时的 thought 文本编码器，且代码会校验它与缓存权重一致 |
| R2R 标注 | `datasets/R2R/annotations/` | Train 和 Val-Unseen 任务 |
| 图结构 | `datasets/R2R/connectivity/` | 最短路径、距离、SPL 等 |
| 可行动作 | `datasets/R2R/navigable/` | 文本环境的状态转移 |
| 场景文本 | `datasets/R2R/observations_list_summarized/` | Policy 当前观测 |
| 历史摘要 | `datasets/R2R/observations_summarized/` | 历史观测上下文 |
| 物体列表 | `datasets/R2R/objects_list/` | 场景物体证据 |
| 固定 Planner 缓存 | `datasets/R2R/action_plan_cache/` | Train/Val-Unseen 均不在训练时重跑 Planner |
| CLIP 缓存 | `datasets/R2R/clip_cache/` | 指令特征和 36-view 原始视觉特征 |
| 固定快评子集 | `datasets/R2R/eval_subsets/` | 保证 Val-Unseen-128 不变 |
| 训练 Python 环境 | `rl-navgpt-container-home/venvs/navgpt-rl/` | 已验证的 Transformers/TRL/PEFT 组合 |
| Level 2 报告 | `outputs/stage6-four-level-20260808-063623/level2_report.json` | 当前正式 token budget 的来源 |

最简单且不容易漏文件的做法，是传输上表两个模型目录和整个
`datasets/R2R/`。注意：`.gitignore` 已经忽略 `models/`、`datasets/*`
和 `outputs/`，因此 `git clone` 不会带上述文件。

### 3.2 仅在断点续训时必须迁移

如果需要从旧机器的某个 checkpoint 续训，必须完整迁移该 run 的
整个输出目录，不能只传 `adapter_model.safetensors`。完整续训还依赖：

- `checkpoint-N/` 内的 LoRA、optimizer、scheduler、Trainer state 和全部 rank RNG；
- run manifest 和 checkpoint manifest；
- `logs/` 中的已完成 rollout 记录；
- `validation/` 中的快照、待评测队列和 best selector 状态。

如果旧 run 在第一个 `save_steps` 之前就退出，它没有可续训的 checkpoint，
无需迁移该 run。

### 3.3 正式训练可以不迁移

| 路径/文件 | 不必须的原因 |
|---|---|
| `datasets/Matterport3D/` | 当前 GRPO 环境使用预计算的 navigable/文本/CLIP 缓存，训练时不实时渲染 RGB |
| `datasets/MP3d/` 中的 zip | 仅用于重新解压原始 Matterport3D |
| MatterSim 编译产物 | 当前正式训练的文本环境不会实时调用 MatterSim |
| `models/*GGUF` | GGUF 用于 Mac/零样本调试，不是 HF LoRA-GRPO 权重 |
| Planner 虚拟环境 | Train/Val-Unseen action plan 都已缓存时不需要再跑 Planner |
| 历史 smoke/test outputs | 不参与新的正式训练 |

但如果要重建 CLIP 视觉缓存、重做 MatterSim RGB 渲染验证，或改变
相机/图像配置，就必须另外迁移 `datasets/Matterport3D/` 和 MatterSim。

## 4. 在旧服务器生成迁移清单

以下操作都在旧服务器宿主机执行，不是在容器中执行。

### 4.1 确认当前容器与挂载

```bash
cd /home/xl/lsl/RL-NavGPT

docker inspect rl-navgpt --format \
'image={{.Config.Image}}
user={{.Config.User}}
working_dir={{.Config.WorkingDir}}
shm_size={{.HostConfig.ShmSize}}
gpus={{json .HostConfig.DeviceRequests}}
{{range .Mounts}}mount={{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

当前已知的两个关键挂载应为：

```text
/home/xl/lsl/RL-NavGPT                 -> /workspace/RL-NavGPT
/home/xl/lsl/rl-navgpt-container-home -> /home/xl
```

保存完整配置：

```bash
MIGRATION_DIR=/home/xl/lsl/migration/navgpt-20260813
mkdir -p "$MIGRATION_DIR"

docker inspect rl-navgpt \
  > "$MIGRATION_DIR/rl-navgpt.container-inspect.json"

docker image inspect "$(docker inspect rl-navgpt --format '{{.Config.Image}}')" \
  > "$MIGRATION_DIR/rl-navgpt.source-image-inspect.json"
```

`docker inspect` 可能包含环境变量，不要将该文件发布到公开仓库。

### 4.2 记录代码状态与 Python 版本

```bash
cd /home/xl/lsl/RL-NavGPT

git rev-parse HEAD \
  > "$MIGRATION_DIR/git-commit.txt"
git status --short \
  > "$MIGRATION_DIR/git-status.txt"
git diff --binary \
  > "$MIGRATION_DIR/uncommitted.patch"

docker exec rl-navgpt bash -lc '
PYTHONNOUSERSITE=1 /home/xl/venvs/navgpt-rl/bin/python -V
PYTHONNOUSERSITE=1 /home/xl/venvs/navgpt-rl/bin/python -m pip freeze
' > "$MIGRATION_DIR/navgpt-rl-pip-freeze.txt"
```

最好在迁移前将本次代码提交到私有 Git 远程。如果
`git-status.txt` 不为空，必须确认未提交文件已经通过 Git、patch 或
rsync 带到新服务器。

### 4.3 停止正在写 checkpoint 的任务

不要在 Trainer 正在写 `checkpoint-N` 时做最终同步：

```bash
docker exec rl-navgpt bash -lc \
  'pgrep -af "train_grpo.py|launch_grpo.py|torch.distributed.run" || true'
```

如果有有效训练进程，可以先对大文件做第一轮 rsync，然后等 checkpoint
完整写入并正常停止训练后，再做一轮最终增量 rsync。

## 5. 迁移 Docker 环境

### 5.1 将当前容器状态提交为镜像

```bash
MIGRATE_IMAGE=rl-navgpt:migrate-20260813

docker commit --pause=true \
  rl-navgpt \
  "$MIGRATE_IMAGE"

docker image inspect "$MIGRATE_IMAGE" \
  --format 'id={{.Id}} size_bytes={{.Size}} user={{.Config.User}}'
```

这一步会保存容器 root filesystem 中的系统库和配置，但不包含两个
bind mount。如果容器环境中设置过 token/密码/代理凭据，不要将该
镜像推送到公开仓库。

### 5.2 导出镜像

首选 `zstd`。先确认旧服务器磁盘足够：

```bash
df -h /home/xl/lsl
command -v zstd
```

然后流式压缩，避免先产生一份未压缩 tar：

```bash
MIGRATION_DIR=/home/xl/lsl/migration/navgpt-20260813
MIGRATE_IMAGE=rl-navgpt:migrate-20260813
IMAGE_ARCHIVE="$MIGRATION_DIR/rl-navgpt-migrate-20260813.tar.zst"

test ! -e "$IMAGE_ARCHIVE"

docker save "$MIGRATE_IMAGE" \
  | zstd -T0 -3 \
  > "$IMAGE_ARCHIVE"

(
  cd "$MIGRATION_DIR"
  sha256sum "$(basename "$IMAGE_ARCHIVE")" \
    > "$(basename "$IMAGE_ARCHIVE").sha256"
)

ls -lh "$IMAGE_ARCHIVE" "$IMAGE_ARCHIVE.sha256"
```

如果磁盘不足，不要在旧服务器额外落一份镜像包；可改用私有
registry，或在网络稳定时通过 SSH 直接流式传输。

## 6. 传输代码、模型、数据和虚拟环境

下面命令假设旧服务器可以直接 SSH 到租用服务器。先在旧服务器
宿主机设置：

```bash
RENTAL_USER=root
RENTAL_HOST=REPLACE_WITH_RENTAL_IP
RENTAL_PORT=22
RENTAL_ROOT=/root/lsl
RENTAL="$RENTAL_USER@$RENTAL_HOST"

ssh -p "$RENTAL_PORT" "$RENTAL" \
  "mkdir -p '$RENTAL_ROOT/migration/navgpt-20260813' \
             '$RENTAL_ROOT/RL-NavGPT/models' \
             '$RENTAL_ROOT/RL-NavGPT/datasets/R2R' \
             '$RENTAL_ROOT/RL-NavGPT/outputs' \
             '$RENTAL_ROOT/rl-navgpt-container-home'"
```

如果实验室服务器不能主动 SSH 到公网，上述直传命令就不能使用。
此时可选：

1. 在本地 Mac 上先从 `xl@192.168.7.202` 下载，再上传到租用服务器；
2. 将镜像与数据传到私有对象存储/私有 registry，由新服务器下载；
3. 向管理员申请临时允许旧服务器访问租用服务器的 SSH 端口。

本地中转会占用一份完整的本地磁盘空间，但流程不变：使用相同相对目录
保存文件，然后对照 `training-inputs.sha256` 在新服务器校验。

### 6.1 传输 Docker 镜像包和迁移记录

```bash
rsync -ah --partial --progress \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/migration/navgpt-20260813/ \
  "$RENTAL:$RENTAL_ROOT/migration/navgpt-20260813/"
```

### 6.2 传输项目代码

推荐在新机器上从私有 Git 仓库 clone，然后 checkout
`git-commit.txt` 记录的提交。如果没有可用的远程仓库，则从旧服务器同步
工作树，但不要在这一步重复传输大模型/数据/输出：

```bash
rsync -ah --partial --progress \
  --exclude '.env' \
  --exclude 'models/' \
  --exclude 'datasets/' \
  --exclude 'outputs/' \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/RL-NavGPT/ \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/"
```

`.env`、SSH 私钥和云服务凭据不应随项目打包；在新服务器上单独创建。

### 6.3 传输两个必需模型

Safetensors 本身已经很紧凑，再用 gzip 通常不会节省太多空间。使用可续传
`rsync` 更合适：

```bash
rsync -ah --partial --progress \
  --exclude '.cache/' \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/RL-NavGPT/models/Qwen2.5-14B-Instruct-1M/ \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/models/Qwen2.5-14B-Instruct-1M/"

rsync -ah --partial --progress \
  --exclude '.cache/' \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/RL-NavGPT/models/clip-vit-large-patch14/ \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/models/clip-vit-large-patch14/"
```

不建议临时在租用机器上下载“同名模型”代替。当前 action-plan manifest
和 CLIP cache manifest 绑定了已验证权重；仓库 revision、权重格式或文件集
不同都可能使指纹校验失败。

### 6.4 传输 R2R 的最小正式训练集合

```bash
R2R_PARTS=(
  annotations
  connectivity
  navigable
  observations_list_summarized
  observations_summarized
  objects_list
  action_plan_cache
  clip_cache
  eval_subsets
)

for PART in "${R2R_PARTS[@]}"; do
  test -d "/home/xl/lsl/RL-NavGPT/datasets/R2R/$PART"

  rsync -ah --partial --progress \
    -e "ssh -p $RENTAL_PORT" \
    "/home/xl/lsl/RL-NavGPT/datasets/R2R/$PART/" \
    "$RENTAL:$RENTAL_ROOT/RL-NavGPT/datasets/R2R/$PART/"
done
```

如果磁盘充足，也可以直接迁移整个 `datasets/R2R/`，只排除旧的临时
实验输出：

```bash
rsync -ah --partial --progress \
  --exclude 'exprs/' \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/RL-NavGPT/datasets/R2R/ \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/datasets/R2R/"
```

上述两种 R2R 传输方式二选一，不需要都执行。

### 6.5 传输 Level 2 token-budget 报告

```bash
LEVEL2_SOURCE=/home/xl/lsl/RL-NavGPT/outputs/stage6-four-level-20260808-063623

test -f "$LEVEL2_SOURCE/level2_report.json"

ssh -p "$RENTAL_PORT" "$RENTAL" \
  "mkdir -p '$RENTAL_ROOT/RL-NavGPT/outputs/stage6-four-level-20260808-063623'"

rsync -ah --partial --progress \
  -e "ssh -p $RENTAL_PORT" \
  "$LEVEL2_SOURCE/level2_report.json" \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/outputs/stage6-four-level-20260808-063623/"
```

### 6.6 传输 `/home/xl` 的容器环境

为了最大限度复制已验证环境，可以迁移整个专用
`rl-navgpt-container-home`。先检查是否包含不应迁移的私钥或 token：

```bash
du -h --max-depth=2 \
  /home/xl/lsl/rl-navgpt-container-home \
  | sort -h | tail -n 40

find /home/xl/lsl/rl-navgpt-container-home \
  -maxdepth 3 \
  \( -name '.ssh' -o -name 'token' -o -name '.env' \) \
  -print
```

确认后传输：

```bash
rsync -aH --partial --progress \
  --exclude '.ssh/' \
  --exclude '.cache/huggingface/token' \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/rl-navgpt-container-home/ \
  "$RENTAL:$RENTAL_ROOT/rl-navgpt-container-home/"
```

如果只进行当前 GRPO 训练，最小必需内容是
`venvs/navgpt-rl/`。`venvs/qwen-tf448/` 仅在重新生成 Planner 缓存时需要；
`src/Matterport3DSimulator/` 仅在需要 MatterSim/重建视觉缓存时需要。

### 6.7 如果需要断点续训，传输完整 run

```bash
RUN_NAME=REPLACE_WITH_REAL_RUN_DIRECTORY_NAME

test -d "/home/xl/lsl/RL-NavGPT/outputs/$RUN_NAME"

rsync -aH --partial --progress \
  -e "ssh -p $RENTAL_PORT" \
  "/home/xl/lsl/RL-NavGPT/outputs/$RUN_NAME/" \
  "$RENTAL:$RENTAL_ROOT/RL-NavGPT/outputs/$RUN_NAME/"
```

训练进程完全退出后再原样运行一次该 rsync，以补齐最后增量文件。

## 7. 校验传输完整性

传输前在旧服务器为正式训练输入生成 SHA256 清单：

```bash
cd /home/xl/lsl/RL-NavGPT

MIGRATION_DIR=/home/xl/lsl/migration/navgpt-20260813

find \
  models/Qwen2.5-14B-Instruct-1M \
  models/clip-vit-large-patch14 \
  datasets/R2R/annotations \
  datasets/R2R/connectivity \
  datasets/R2R/navigable \
  datasets/R2R/observations_list_summarized \
  datasets/R2R/observations_summarized \
  datasets/R2R/objects_list \
  datasets/R2R/action_plan_cache \
  datasets/R2R/clip_cache \
  datasets/R2R/eval_subsets \
  outputs/stage6-four-level-20260808-063623/level2_report.json \
  -type f -print0 \
  | sort -z \
  | xargs -0 sha256sum \
  > "$MIGRATION_DIR/training-inputs.sha256"
```

该命令会读取约 30 GB Qwen 权重，需要一些时间，但能发现静默传输
损坏。生成清单后再同步迁移记录目录：

```bash
rsync -ah --partial --progress \
  -e "ssh -p $RENTAL_PORT" \
  /home/xl/lsl/migration/navgpt-20260813/ \
  "$RENTAL:$RENTAL_ROOT/migration/navgpt-20260813/"
```

## 8. 在租用服务器恢复

以下操作改为在租用服务器宿主机执行。

### 8.1 检查宿主机 GPU 和 Docker

```bash
uname -m
nvidia-smi
docker version
docker info | sed -n '1,100p'
```

`uname -m` 应为 `x86_64`。如果 `docker run --gpus` 无法识别 GPU，需要由
平台或管理员安装/配置 NVIDIA Container Toolkit，不是在容器内重装
CUDA 就能解决。

### 8.2 校验并导入 Docker 镜像

```bash
RENTAL_ROOT=/root/lsl
MIGRATION_DIR="$RENTAL_ROOT/migration/navgpt-20260813"
IMAGE_ARCHIVE="$MIGRATION_DIR/rl-navgpt-migrate-20260813.tar.zst"

cd "$MIGRATION_DIR"
sha256sum -c "$IMAGE_ARCHIVE.sha256"

zstd -dc "$IMAGE_ARCHIVE" \
  | docker load

docker image inspect rl-navgpt:migrate-20260813 \
  --format 'id={{.Id}} size_bytes={{.Size}} user={{.Config.User}}'
```

### 8.3 校验模型和数据

```bash
cd "$RENTAL_ROOT/RL-NavGPT"

sha256sum -c \
  "$MIGRATION_DIR/training-inputs.sha256"
```

所有条目都应输出 `OK`。如果只有某个文件失败，只需重新 rsync 对应
目录，不要重新上传整个项目。

### 8.4 恢复相同容器路径

宿主机的目录可以放在 `/root/lsl`、数据盘或任意位置；但容器内路径
应继续保持 `/workspace/RL-NavGPT` 和 `/home/xl`，否则虚拟环境脚本、MatterSim
扩展和现有运行命令中的绝对路径会失效。

先检查目录所有者：

```bash
stat -c '%u:%g %n' \
  "$RENTAL_ROOT/RL-NavGPT" \
  "$RENTAL_ROOT/rl-navgpt-container-home"

docker image inspect rl-navgpt:migrate-20260813 \
  --format 'image_user={{.Config.User}}'
```

原容器使用 UID/GID 1009。如果 rsync 没有保留数字 owner，而新镜像仍以
1009:1009 运行，就需要在新服务器调整这两个专用目录：

```bash
chown -R 1009:1009 \
  "$RENTAL_ROOT/RL-NavGPT" \
  "$RENTAL_ROOT/rl-navgpt-container-home"
```

仅对上述两个已确认的专用目录执行，不要对 `/root`、`/home` 或数据盘
根目录递归 `chown`。

确认没有同名容器后启动：

```bash
test -d "$RENTAL_ROOT/RL-NavGPT"
test -d "$RENTAL_ROOT/rl-navgpt-container-home"
test -z "$(docker ps -aq --filter name='^/rl-navgpt$')"

docker run -d \
  --name rl-navgpt \
  --gpus all \
  --shm-size=32g \
  --ipc=private \
  --env NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics \
  --mount \
    type=bind,src="$RENTAL_ROOT/RL-NavGPT",dst=/workspace/RL-NavGPT \
  --mount \
    type=bind,src="$RENTAL_ROOT/rl-navgpt-container-home",dst=/home/xl \
  --workdir /workspace/RL-NavGPT \
  rl-navgpt:migrate-20260813 \
  sleep infinity

docker ps --filter name='^/rl-navgpt$'
```

如果镜像的 `Config.User` 为空，但希望严格复制原容器的 UID/GID，可在
`docker run` 中增加 `--user 1009:1009`。容器中显示
`I have no name!` 只表示 `/etc/passwd` 中没有 UID 1009 的名字映射，不影响训练。

### 8.5 恢复 Level 2 路径指针

`/tmp/navgpt-stage6-validation-root` 属于原容器的临时文件，不会随项目或
Docker 数据盘自动迁移。为兼容现有训练命令，在新容器重建：

```bash
docker exec rl-navgpt bash -lc '
```

这样就不再依赖容器 `/tmp` 中的临时指针。

### 9.4 根据新 GPU 选择 NCCL profile

`blackwell-safe` 是针对原实验室“PCIe RTX PRO 6000 Blackwell +
特定驱动/NCCL”验证的兼容配置，它禁用了 P2P、SHM 和 IB，不是
A100/H100 的通用加速配置。

- 租用 A100/H100/H200 等常规机器：先使用 `--nccl-profile default`；
- 租用与原机器相同的 PCIe Blackwell，且默认 NCCL 出现 illegal memory
  access/Xid 13：再改用 `blackwell-safe`；
- 单卡模式不使用 NCCL 集合通信，使用 `default`。

例如租用两张 A100/H100 时，先做 dry-run：

```bash
PYTHONNOUSERSITE=1 "$TRAIN_PYTHON" \
  scripts/launch_grpo.py \
    --mode ddp \
    --gpus 0,1 \
    --nccl-profile default \
    --dry-run \
    -- \
    --max-completion-length 38912 \
    --r 16
```

输出命令应包含 `--nproc_per_node=2 --` 和 `train_grpo.py`。

### 9.5 真实 1-step smoke test

在新硬件上不要直接启动几天的正式训练。先用实际 GPU 数量跑一个
optimizer step。以两卡为例：


验收条件：

## 10. 云平台不允许 `docker load` 时

某些租卡平台本身已经把用户放在容器内，用户无法再操作 Docker daemon。
按以下优先级处理：

1. 如平台支持自定义镜像，将迁移镜像推送到私有 registry，直接从该
   镜像创建实例；
2. 如只能选择平台预置镜像，尽量选择
   `pytorch/pytorch:2.7.1-cuda12.8-cudnn9-devel` 或对应的
   PyTorch 2.7.1/CUDA 12.8/Python 3.11 环境；
3. 将项目放到 `/workspace/RL-NavGPT`，将原 container-home 放到
   `/home/xl`，再测试原 `navgpt-rl` venv 能否执行；
4. 如旧 venv 因基础 Python 路径不同而无法运行，才重建环境。

重建训练环境的最小方式为：

```bash
mkdir -p /home/xl/venvs

python3 -m venv --system-site-packages \
  /home/xl/venvs/navgpt-rl

/home/xl/venvs/navgpt-rl/bin/python -m pip install --upgrade pip

/home/xl/venvs/navgpt-rl/bin/python -m pip install \
  -r /workspace/RL-NavGPT/requirements-train.txt
```

然后必须重新执行第 9 节的所有版本、缓存、契约和 1-step 验证。
这是“重建环境”，其复现性低于直接迁移已验证 Docker 镜像。

## 12. 正式训练和数据保护

### 12.1 启动正式训练

迁移验收和 1-step smoke test 全部通过后，使用
`docs/训练命令.md` 中的正式命令。需要针对新硬件确认的只有：

- `--mode single` 或 `--mode ddp`；
- `--gpus 0`、`0,1` 或 `0,1,2,3`；
- `--nccl-profile default` 或确有必要时的 `blackwell-safe`；
- 磁盘容量、快评周期和总训练 step。

### 12.2 租用实例必须定期备份

租用 GPU 服务器的系统盘可能在释放实例后删除。正式训练期间至少备份：

- 最新的完整 `checkpoint-N/`；
- quick-best/full-best 的 adapter 和 selector 状态；
- run manifest、Git commit/status；
- `logs/train_metrics.jsonl` 和 rollout/评测记录；
- 训练完成后的 `final-adapter-step-N/`。

备份到本地、持久数据盘或对象存储，不要只留在 GPU 实例的临时系统盘。

## 13. 常见错误

### 13.1 `git clone` 后提示模型或数据不存在

原因：`models/`、`datasets/*` 和 `outputs/` 被 `.gitignore` 忽略。

处理：按第 6 节单独 rsync，不是重新 clone。

### 13.2 镜像导入后 `/home/xl/venvs/navgpt-rl` 不存在

原因：`/home/xl` 原来是 bind mount，`docker commit` 不会收录。

处理：迁移 `rl-navgpt-container-home` 并重新挂载到 `/home/xl`。

### 13.3 PyTorch 看不到 GPU

原因通常在新宿主机的 NVIDIA driver/Container Toolkit，或容器启动时没有
`--gpus all`。

处理：先在宿主机运行 `nvidia-smi`，再检查 Docker GPU runtime；不要先在
venv 里反复重装 torch。

### 13.4 CLIP cache 报权重 SHA256 不一致

原因：新机器重新下载了另一份 CLIP 权重，或传输不完整。

处理：重新 rsync 旧服务器已验证的整个
`models/clip-vit-large-patch14/`，然后重跑 SHA256 和 cache verify。

### 13.5 A100/H100 训练速度异常慢

检查是否不必要地使用了 `blackwell-safe`。该 profile 为了规避原 Blackwell
机器的 NCCL 错误而禁用了多个高速传输路径。在新机器通过默认 NCCL
smoke test 后，应使用 `--nccl-profile default`。
