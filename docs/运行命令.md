# NavGPT 推理运行命令

三个后端共享同一套导航 Prompt 和输出协议：

```text
<Think>基于指令、场景和历史的简洁推理</Think>
<Action>action_maker("32位viewpoint_id")</Action>
```

到达终点时：

```text
<Think>已经满足终点描述，可以停止</Think>
<Action>Finish!</Action>
```

命令行默认仍是 `planner`：先让当前后端模型把原始 instruction 拆分为
action plan，再把 action plan 交给逐步导航策略，用于在线基线与调试。
正式 GRPO 训练及训练后主实验使用 `action_plan` 加独立 JSONL 缓存；
`instruction` 保留为消融模式。

## 1. GGUF / llama.cpp（当前 Mac 调试模型）

```bash
cd nav_src

python3 NavGPT.py \
  --llm_backend gguf \
  --llm_model_name qwen2.5-14b-instruct \
  --local_model_path /Users/bigcat/Documents/MyCode/NavGPT/models/Qwen2.5-14B-Instruct-1M-Q4_K_M.gguf \
  --local_chat_template qwen \
  --navigation_input_mode planner \
  --output_dir ../datasets/R2R/exprs/qwen2.5-14b-gguf-planner \
  --temperature 0 \
  --max_new_tokens 256 \
  --gguf_n_ctx 4096 \
  --gguf_n_gpu_layers 48 \
  --iters 2
```

`qwen` 会让 GGUF 后端使用 ChatML；如果 GGUF 自带且能被
`llama.cpp` 正确识别聊天模板，可以使用 `--local_chat_template auto`。

## 2. Hugging Face 模型（14B 训练/基线权重）

HF 后端会调用 tokenizer 自带的 `apply_chat_template()`，不会手写
Qwen 特殊 token。以下目录中应包含 8 份 `.safetensors` 权重分片：

```bash
cd nav_src

python3 NavGPT.py \
  --llm_backend hf \
  --llm_model_name qwen2.5-14b-instruct-1m \
  --local_model_path ../models/Qwen2.5-14B-Instruct-1M \
  --local_chat_template auto \
  --local_dtype bf16 \
  --hf_device_map single \
  --navigation_input_mode planner \
  --output_dir ../datasets/R2R/exprs/qwen2.5-14b-hf-planner \
  --temperature 0 \
  --max_new_tokens 256 \
  --iters 2
```

`plain` 只应用于明确要求原始 completion prompt 的本地模型。
14B BF16 权重自身约 29.6GB，当前 16GB Apple Silicon 机器不适合直接
加载或训练该 HF 模型；本机继续使用 GGUF 做推理调试，HF 目录用于后续
拷贝到训练服务器或在足够显存/内存的机器上运行。

## 3. OpenAI 在线模型

先在项目根目录的 `.env` 中配置 `OPENAI_API_KEY`，然后运行：

```bash
cd nav_src

python3 NavGPT.py \
  --llm_backend openai \
  --llm_model_name gpt-3.5-turbo \
  --navigation_input_mode planner \
  --output_dir ../datasets/R2R/exprs/openai-planner \
  --temperature 0 \
  --iters 2
```

在线后端直接接收中性的导航 Prompt，不会被套入 Qwen ChatML。

## 4. 完整零样本基线

确认 2 条样例能够稳定输出合法 Think/Action 后，将独立实验目录中的
`--iters` 改为 `-1`，即可遍历完整 split：

```bash
python3 NavGPT.py \
  ... \
  --val_env_name R2R_val_unseen_instr \
  --iters -1
```

## 5. 固定 Planner：生成训练集 action plan 缓存

以下命令在服务器容器的 `/workspace/RL-NavGPT` 中执行。缓存是派生数据，
不会修改 `R2R_train_enc.json`。四个任务各自只看到一张 GPU，不能使用
`device_map=auto` 跨卡切层。

### 5.1 固定路径和环境

```bash
cd /workspace/RL-NavGPT/nav_src

PLANNER_PYTHON=/home/xl/venvs/qwen-tf448/bin/python
PLANNER_ANNOTATION=../datasets/R2R/annotations/R2R_train_enc.json
PLANNER_MODEL=../models/Qwen2.5-14B-Instruct-1M
PLANNER_CACHE=../datasets/R2R/action_plan_cache/qwen2.5-14b-train-t0-v1

mkdir -p "$PLANNER_CACHE"

PYTHONNOUSERSITE=1 "$PLANNER_PYTHON" -c \
  'import torch, transformers; print(torch.__version__, torch.__file__); print(transformers.__version__, transformers.__file__)'
```

最后一条应显示当前已经验证的 PyTorch 环境和
`transformers 4.48.3`。如服务器虚拟环境尚未安装项目依赖：

```bash
"$PLANNER_PYTHON" -m pip install -r ../requirements-planner.txt
```

### 5.2 先用 shard 0 生成两条，验证断点续跑

```bash
PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES=0 \
  "$PLANNER_PYTHON" scripts/action_planner.py generate \
  --annotation "$PLANNER_ANNOTATION" \
  --output "$PLANNER_CACHE/shard-0.jsonl" \
  --shard-id 0 \
  --num-shards 4 \
  --expected-count 14039 \
  --local-model-path "$PLANNER_MODEL" \
  --model-id Qwen/Qwen2.5-14B-Instruct-1M \
  --model-revision modelscope-master-fileset-46627f7a9e85 \
  --expected-transformers-version 4.48.3 \
  --chat-template auto \
  --dtype bf16 \
  --temperature 0 \
  --top-p 0.9 \
  --max-new-tokens 256 \
  --seed 0 \
  --stop-after 2

wc -l "$PLANNER_CACHE/shard-0.jsonl"
head -n 1 "$PLANNER_CACHE/shard-0.jsonl" | \
  "$PLANNER_PYTHON" -m json.tool
```

`wc -l` 应为 2，manifest 状态应为 `partial`。再次运行不带
`--stop-after` 的 shard 0 命令会从第三条继续，不会覆盖前两条。脚本已经
内置并记录八个已校验权重分片的 SHA256；若要在生成前再次完整读取并
校验约 29.6GB 权重，可只在这次 smoke 命令追加
`--verify-weight-sha256`。

### 5.4 合并并强制校验 14,039 个唯一 instr_id

```bash
"$PLANNER_PYTHON" scripts/action_planner.py merge \
  --annotation "$PLANNER_ANNOTATION" \
  --inputs \
    "$PLANNER_CACHE/shard-0.jsonl" \
    "$PLANNER_CACHE/shard-1.jsonl" \
    "$PLANNER_CACHE/shard-2.jsonl" \
    "$PLANNER_CACHE/shard-3.jsonl" \
  --output "$PLANNER_CACHE/R2R_train_action_plans.jsonl" \
  --num-shards 4 \
  --expected-count 14039

wc -l "$PLANNER_CACHE/R2R_train_action_plans.jsonl"
"$PLANNER_PYTHON" -m json.tool \
  "$PLANNER_CACHE/R2R_train_action_plans.jsonl.manifest.json"
```

成功信息必须包含
`Merged 14039 records with 14039 unique instr_id values`；manifest 中
`record_count` 与 `unique_instr_id_count` 也都必须是 14039。

## 6. 第三步：验证 Gymnasium / TRL 强化学习环境包装器

第三步不加载 14B 模型，也不占用 GPU；它使用真实 R2R annotation、场景
文本、导航图和第 5 节生成的 action plan 缓存，逐项检查环境状态机。

### 6.1 建立独立训练环境

不要在固定 Planner 的 `qwen-tf448` 虚拟环境中安装训练依赖：Planner
需要保持 `transformers 4.48.3`，而 TRL 的有状态 `environment_factory`
需要 `transformers>=5.2`。在容器中建立单独虚拟环境：

```bash
cd /workspace/RL-NavGPT/nav_src

TRAIN_VENV=/home/xl/venvs/navgpt-rl
python3 -m venv --system-site-packages "$TRAIN_VENV"
TRAIN_PYTHON="$TRAIN_VENV/bin/python"

"$TRAIN_PYTHON" -m pip install --upgrade pip
"$TRAIN_PYTHON" -m pip install -r ../requirements-train.txt

PYTHONNOUSERSITE=1 "$TRAIN_PYTHON" -c \
  'import gymnasium, transformers, trl; print("gymnasium", gymnasium.__version__); print("transformers", transformers.__version__); print("trl", trl.__version__)'
```

若 `TRAIN_VENV` 已存在，不要重复执行 `python3 -m venv`，直接从
`TRAIN_PYTHON=...` 继续即可。

### 6.2 运行真实数据 smoke test

```bash
cd /workspace/RL-NavGPT/nav_src

TRAIN_PYTHON=/home/xl/venvs/navgpt-rl/bin/python
PLANNER_CACHE=../datasets/R2R/action_plan_cache/qwen2.5-14b-train-t0-v1

PYTHONNOUSERSITE=1 "$TRAIN_PYTHON" scripts/validate_rl_env.py \
  --root-dir ../datasets \
  --split R2R_train_enc \
  --action-plan-cache \
    "$PLANNER_CACHE/R2R_train_action_plans.jsonl" \
  --instr-id 6250_0 \
  --max-steps 20
```

最后必须输出 `PASS instr_id=6250_0`，并通过以下检查：

- 同一 `instr_id` 重置后 action plan、起点、朝向和初始 Prompt 完全一致；
- 相邻移动、非法 ID no-op、回溯、提前停止、成功停止和最大步数截断；
- `terminated` 与 `truncated` 语义正确，成功只由 3m 内主动 `Finish!` 触发；
- 上一步/当前步视觉特征能随 transition 交给后续复合奖励；
- Gymnasium 官方环境检查器通过；
- 同一 GRPO group 的模拟器与奖励状态隔离，同时共享只读导航图缓存；
- 创建 rollout 不改变 Python 全局随机数状态；
- TRL 零参数 factory 只公开一个策略动作入口，不会误公开 Gym 辅助方法。

第三步的 `stage3_placeholder` 奖励固定为 `0.0` 是预期行为。基础导航、
CLIP 语义对齐和思维质量奖励将在第四步接入同一个 transition，不应提前
混入本次环境状态机验证。
