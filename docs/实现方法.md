## 1. RL 成员

| 标准 RL 术语 | 在本 VLN 方案中的含义 | 具体实现 |
| --- | --- | --- |
| 智能体（Agent） | 带 LoRA 的本地 LLM 决策层 | 主干冻结，仅更新 LoRA；输出统一的 `<Think>...</Think><Action>...</Action>` |
| 环境（Environment） | R2R 图环境 + 固定场景文本 + CLIP 特征缓存 + Prompt 管理器 | 重置任务、执行 viewpoint 动作、维护历史、累计环境奖励 |
| 状态（State） | 与推理完全一致的完整导航 Prompt | 正式训练默认读取固定 Planner 的 action plan JSONL 缓存，并包含当前场景文本和历史；原始 instruction 作为消融选项 |
| 动作（Action） | 结构化思考与动作序列 | `action_maker("viewpoint_id")`、`back_tracer("viewpoint_id")` 或 `Finish!` |
| 奖励（Reward） | 三类复合奖励 | 基础导航、CLIP 跨模态语义对齐、思维质量 |
| 轨迹（Trajectory） | 一次有状态多轮导航交互 | 保存每步 Prompt、Think/Action、分项奖励、状态变化和结束原因 |

当前 NavGPT 主流程读取预生成的场景文本 JSON，并不会在线返回原始
RGB。CLIP 创新保持不变，但实现前必须额外准备 Matterport3D 原始视图，
并推荐离线缓存每个 viewpoint/朝向的 CLIP 图像特征。

## 2. 训练流程

### 阶段 2：在线交互收集数据

这个阶段让**带 LoRA 的 LLM 智能体**在固定黑盒环境中反复执行导航任务，收集完整的轨迹数据，用于后续 GRPO 训练：

1. **重置环境**：从 R2R 训练集选择一条任务，恢复起点和初始朝向；
   默认读取由固定 Planner 离线生成、且与在线基线逐字符一致的 action
   plan JSONL 缓存，加载指令 CLIP
   文本特征，返回初始 Prompt；
2. **智能体决策**：把 s0 喂给带 LoRA 的 LLM，模型输出结构化结果 `<Think>...</Think><Action>...</Action>`；
3. **环境执行动作**：统一解析器提取 thought 和动作，图环境移动到下一
   viewpoint；Prompt 管理器读取预生成场景文本并打包新状态，同时读取
   对应的预计算 CLIP 图像特征；
4. 环境计算复合奖励：
   - 计算基础导航奖励：根据距离变化、是否回头路、是否撞墙 / 超时给出基础分；
   - 计算语义对齐奖励：提取当前观测图像的 CLIP 视觉特征，与指令文本特征
     计算余弦相似度，使用有终局比例硬上限的端点势函数差给出奖励；
   - 计算思维质量辅助信号：文本子目标对齐仅记录诊断；只奖励被环境执行并由
     唯一方向/viewpoint 支持的动作或确认成功的 Finish，同时惩罚明确矛盾；
   - 三项加权求和得到单步总奖励 r0；
5. **存下轨迹数据**：把 (s0, 完整输出，r0, s1) 存入轨迹缓冲区，保留分项奖励与思考内容；
6. **循环交互**：重复步骤 2-5，直到机器人到达终点（成功）或超时 / 死胡同（失败），完成一条完整轨迹；
7. **批量收集**：重复步骤 1-6，收集数十至数百条轨迹，攒够一个 Batch 的训练数据。

------

### 阶段 3：RL 训练更新参数（核心，只更新 LoRA）

这个阶段用收集到的轨迹数据，通过 GRPO 算法**只更新 LoRA 适配器的参数**，LLM 主干权重完全不动，实现思考与动作的协同优化：

1. **创建同起点 rollout group**：同一 group 共享 instruction、planner
   action plan、起点和初始朝向，只改变策略采样结果；
2. **在线多轮交互**：TRL 通过 `environment_factory` 创建隔离环境实例，
   环境执行工具动作并累计 episode 奖励；
3. **计算回报与优势**：对组内 episode 复合奖励归一化；思考段与动作段
   共享优势信号，梯度同步回传；
4. GRPO 算法更新：调用 Hugging Face TRL 库的 GRPOTrainer：
   - 策略网络：带 LoRA 的 LLM；
   - 参考模型：初始 SFT 前的零样本模型，用于 KL 散度约束，避免策略跑偏；
   - 损失函数：GRPO 标准损失，带 KL 惩罚项，同时优化思考文本与动作指令的输出分布；
5. **只更新 LoRA**：训练过程中 LLM 主干权重冻结，仅 LoRA 参数更新；
6. **验证与保存**：定期在验证集测评 SR、SPL、语义匹配度、思考一致性；
7. **循环迭代**：重复在线 rollout 与策略更新，直至验证指标收敛。

------

不用自己写 RL 底层代码，直接使用 Hugging Face 的 **TRL（Transformer Reinforcement Learning）库**，其中 `GRPOTrainer` 已原生支持 LLM 的 RL 微调。你只需要实现：

1. 环境交互函数：负责让 LLM 在仿真中跑导航、输出结构化结果、收集完整轨迹；
2. 复合奖励函数：实现基础导航、语义对齐、思维质量三类奖励的计算逻辑；
3. 调用 `GRPOTrainer`，传入 `environment_factory`、LLM、LoRA 配置和
   奖励函数，启动有状态多轮训练。

------

## 3. 加入 RL 后的「推理流程」

**核心重点：推理的时候，RL 模块完全不工作！**

训练完成后，仅用「冻结的 LLM 主干 + 训练好的 LoRA 适配器」替换原版 NavGPT 中的 LLM，其余所有环节（MLLM、Prompt 管理器、仿真环境）完全不动。推理流程和原版 NavGPT 100% 兼容，为纯前向推理，无任何 RL 组件。

### 完整推理流程（4 步，和原版 NavGPT 完全对齐）

1. **加载模型**：加载「冻结的 LLM 主干 + 训练好的 LoRA 适配器」，可通过 PEFT 库直接加载，无需合并权重；
2. **环境初始化**：加载一条新的导航指令，将机器人放到起点，MLLM 把初始画面转成文本，Prompt 管理器打包成初始 Prompt；
3. 纯前向推理循环：
   - 把当前 Prompt 喂给训练好的 LLM；
   - LLM 纯前向推理，输出结构化的 `<Think>推理过程</Think><Action>动作指令</Action>`；
   - 执行动作，机器人移动，获取新画面，MLLM 转文本，打包新 Prompt；
   - 重复该过程，直到 LLM 输出 `Finish!`；
4. **结束**：导航完成。相比原版 NavGPT，训练后的模型规划更稳定、回头路更少、长指令遗忘问题显著改善，同时思考过程逻辑更自洽、可解释性更强。

## 4. 完整流程

1. **环境准备**：加载 R2R 图环境、预生成场景文本和导航图；准备
   Matterport3D 视觉视图并缓存 CLIP 图像特征，同时预计算指令文本特征；
2. **模型初始化**：加载论文主模型
   `Qwen2.5-14B-Instruct-1M` 的 HF Safetensors 权重，挂载 LoRA
   适配器，**100% 冻结 LLM 主干权重，仅放开 LoRA 参数可训练**；
   GGUF Q4_K_M 仅用于推理基线，不参与 PEFT 训练；配置模型输出为
   「思考 + 动作」结构化格式；
3. **RL 交互收集数据**：从 R2R 训练集随机抽取导航指令，将机器人置于对应起点，让带 LoRA 的 LLM 在仿真中执行导航，与环境交互，收集完整轨迹数据（每步的状态、完整输出、三类分项奖励、下一状态）；
4. **RL 训练更新参数**：用收集到的轨迹数据，调用 TRL 库的 GRPO 算法，**仅更新 LoRA 适配器参数**，同步优化思考质量与动作准确率；
5. **循环迭代**：重复「抽指令 → 交互收数据 → 训 LoRA」的闭环，每训练若干轮就在 R2R 验证集上测评 SR、SPL、语义匹配度、思考一致性等指标，保存效果最优的 LoRA 权重；
6. **推理验证**：训练完成后，将训好的 LoRA 插回原 LLM，在 R2R 测试集上执行推理，与零样本基线、原版 NavGPT 对比指标，验证各创新点的有效性。
