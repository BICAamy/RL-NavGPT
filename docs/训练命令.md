# Qwen2.5-14B LoRA-GRPO 正式训练命令

本文档给出 8.1 主对比实验中 Ours（14B 本地模型 + 完整三类奖励 RL）的正式
训练、监控和断点续训命令。概念解释见
[`docs/训练流程与讲解.md`](训练流程与讲解.md)。

对比组 1 中的 NavGPT GPT-3.5 是零样本基线，不需要训练；下面训练的仅是 Ours。

## 1. 已验证的正式配置

当前服务器与代码已真实通过：

- 4 × NVIDIA RTX PRO 6000 Blackwell Server Edition；
- Qwen2.5-14B BF16 + LoRA；
- 4-GPU DDP、同任务 4 rollout、LoRA-only 梯度同步；
- `blackwell-safe` NCCL transport；
- 连续训练与 checkpoint 恢复逐张量一致；
- Level 2 全量 token 审计上界，当前
  `recommended_max_completion_length=38912`；
- RTX PRO 6000 Blackwell 96GB 的正式训练硬上限使用
  `max_completion_length=8192`，防止极端长 completion 在反向传播时触发 OOM。

正式训练使用 R2R train 的 14,039 条 instruction。考虑两到三天的运行预算，
本文档采用固定 optimizer-step 上限：四卡模板为 2500 steps，两卡参数组为
1500 steps；每个 step 都包含同一任务的 4 条 rollout。两者训练长度不同，不能
当作同一个 run，也不能相互恢复 checkpoint。不要用此前 1/2-step smoke test
的耗时直接估算完整训练耗时。

### 2.1 首次训练前生成 Val-Unseen 的固定 Planner 缓存

训练集 Planner 缓存不能用于 Val-Unseen。以下操作只需成功完成一次；中断后
原命令重跑会从各 shard 已完成的位置继续：

```bash
cd /workspace/RL-NavGPT/nav_src

PLANNER_PYTHON=/home/xl/venvs/qwen-tf448/bin/python
PLANNER_MODEL=../models/Qwen2.5-14B-Instruct-1M
VAL_ANNOTATION=../datasets/R2R/annotations/R2R_val_unseen_instr.json
VAL_PLAN_DIR=../datasets/R2R/action_plan_cache/qwen2.5-14b-val-unseen-t0-v1

mkdir -p "$VAL_PLAN_DIR"

for SHARD_ID in 0 1 2 3; do
  nohup env \
    CUDA_VISIBLE_DEVICES="$SHARD_ID" \
    PYTHONNOUSERSITE=1 \
    PYTHONUNBUFFERED=1 \
    "$PLANNER_PYTHON" scripts/action_planner.py generate \
      --annotation "$VAL_ANNOTATION" \
      --output "$VAL_PLAN_DIR/shard-$SHARD_ID.jsonl" \
      --shard-id "$SHARD_ID" \
      --num-shards 4 \
      --expected-count 2349 \
      --local-model-path "$PLANNER_MODEL" \
      --model-id Qwen/Qwen2.5-14B-Instruct-1M \
      --model-revision modelscope-master-fileset-46627f7a9e85 \
      --expected-transformers-version 4.48.3 \
      --chat-template auto \
      --dtype bf16 \
      --temperature 0 \
      --top-p 0.9 \
      --max-new-tokens 256 \
      --seed 0 \
    > "$VAL_PLAN_DIR/shard-$SHARD_ID.log" 2>&1 &
done
```

监控：

```bash
wc -l "$VAL_PLAN_DIR"/shard-[0-3].jsonl
tail -f "$VAL_PLAN_DIR/shard-0.log"
```

四个 shard 完成数量应为 `588 587 587 587`。全部完成后合并：

```bash
PYTHONNOUSERSITE=1 "$PLANNER_PYTHON" \
  scripts/action_planner.py merge \
    --annotation "$VAL_ANNOTATION" \
    --inputs \
      "$VAL_PLAN_DIR/shard-0.jsonl" \
      "$VAL_PLAN_DIR/shard-1.jsonl" \
      "$VAL_PLAN_DIR/shard-2.jsonl" \
      "$VAL_PLAN_DIR/shard-3.jsonl" \
    --output "$VAL_PLAN_DIR/R2R_val_unseen_action_plans.jsonl" \
    --num-shards 4 \
    --expected-count 2349

test -f "$VAL_PLAN_DIR/R2R_val_unseen_action_plans.jsonl.manifest.json"
wc -l "$VAL_PLAN_DIR/R2R_val_unseen_action_plans.jsonl"
```

最后必须是 2349。正式训练启动时会再次逐条校验 instruction、action plan、
Planner fingerprint 和 manifest；缺一条都会在加载 14B Policy 前停止。

先运行不加载 Qwen/CLIP 的最小契约测试：

```bash
TRAIN_PYTHON=/home/xl/venvs/navgpt-rl/bin/python

PYTHONNOUSERSITE=1 "$TRAIN_PYTHON" \
  scripts/validate_r2r_evaluation.py
```

最后应输出 `PASS R2R validation contract`。固定子集文件一旦创建，annotation、
seed、数量或 ID 有任何变化都会报错，不会静默重选 128 条样本。

## 3. 读取审计上界并设置 8192 训练上限

Level 2 报告给出的是最坏情况下不截断完整多轮 transcript 的**理论审计上界**，
不是某张 GPU 已验证可承受的训练长度。当前数据对应的审计上界为 38912；实测
Qwen2.5-14B 在 96GB RTX PRO 6000 Blackwell 上可能因极端长 completion 超过
单卡显存，因此正式主实验使用 8192 作为**硬件安全训练上限**。

正式训练仍然读取 Level 2 报告以保留审计依据，但不能把 Level 3/4 的 smoke
budget 当作审计上界：

```bash
cd /workspace/RL-NavGPT/nav_src

TRAIN_PYTHON=/home/xl/venvs/navgpt-rl/bin/python
VALIDATION_ROOT=$(cat /tmp/navgpt-stage6-validation-root)
LEVEL2_REPORT=$(realpath "$VALIDATION_ROOT/level2_report.json")

test -f "$LEVEL2_REPORT"

AUDITED_MAX_COMPLETION_LENGTH=$(
  "$TRAIN_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["token_budget"]["recommended_max_completion_length"])' \
  "$LEVEL2_REPORT"
)

TRAIN_MAX_COMPLETION_LENGTH=8192

echo "LEVEL2_REPORT=$LEVEL2_REPORT"
echo "AUDITED_MAX_COMPLETION_LENGTH=$AUDITED_MAX_COMPLETION_LENGTH"
echo "TRAIN_MAX_COMPLETION_LENGTH=$TRAIN_MAX_COMPLETION_LENGTH"

test "$AUDITED_MAX_COMPLETION_LENGTH" -gt 0
test "$TRAIN_MAX_COMPLETION_LENGTH" -gt 0
test "$TRAIN_MAX_COMPLETION_LENGTH" -le \
  "$AUDITED_MAX_COMPLETION_LENGTH"
```

当前代码和数据对应的预期输出是：

```text
AUDITED_MAX_COMPLETION_LENGTH=38912
TRAIN_MAX_COMPLETION_LENGTH=8192
```

若审计值不是 38912，不要篡改报告；先确认是否读取了另一轮 Level 2 结果。
训练值 8192 是本次主实验的固定超参数，所有主实验种子和奖励消融必须一致。
38912 只用于说明理论覆盖范围，不能再直接传给正式训练。训练日志中的
`completions/clipped_ratio` 用于检查 8192 是否实际截断 completion。
此前以 38912 启动并 OOM 的 run 不能改参数后续训；必须使用第 4 节命令创建
新的 `RUN_TAG` 和输出目录。

### 3.1 最后一次真实四卡闭环验收

上传本批代码后、正式长训练前只运行一次。它使用真实 Qwen、真实 GRPO 和从
Val-Unseen 固定截取的 16 条临时 fixture，但不把 fixture 分数当论文结果。

脚本会自动执行：训练 step 1 → 在 fast job 已持久化后终止 torchrun → 以
`--validation-only` 恢复评测且不训练 → 从 checkpoint-1 恢复到 step 2 → 完成
第二次快评与 epoch-end 完整 fixture 评测 → 检查 quick/full best。

```bash
set -e

cd /workspace/RL-NavGPT/nav_src

TRAIN_PYTHON=/home/xl/venvs/navgpt-rl/bin/python
VALIDATION_ROOT=$(cat /tmp/navgpt-stage6-validation-root)
LEVEL2_REPORT=$(realpath "$VALIDATION_ROOT/level2_report.json")

AUDITED_MAX_COMPLETION_LENGTH=$(
  "$TRAIN_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["token_budget"]["recommended_max_completion_length"])' \
  "$LEVEL2_REPORT"
)
TRAIN_MAX_COMPLETION_LENGTH=8192

test "$TRAIN_MAX_COMPLETION_LENGTH" -le \
  "$AUDITED_MAX_COMPLETION_LENGTH"

CYCLE_ROOT="../outputs/grpo-validation-cycle-$(date +%Y%m%d-%H%M%S)"
test ! -e "$CYCLE_ROOT"

PYTHONNOUSERSITE=1 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
TRL_EXPERIMENTAL_SILENCE=1 \
TOKENIZERS_PARALLELISM=false \
OMP_NUM_THREADS=1 \
"$TRAIN_PYTHON" scripts/validate_grpo_validation_cycle.py \
  --validation-root "$CYCLE_ROOT" \
  --gpus 0,1,2,3 \
  --nccl-profile blackwell-safe \
  --max-completion-length "$TRAIN_MAX_COMPLETION_LENGTH"
```

最终必须输出：

```text
PASS real four-GPU train/evaluate/resume validation
- training was interrupted with fast-step-1 persisted in the queue
- evaluation-only drained the queue without an optimizer step
- checkpoint-1 resumed through step 2 and epoch-end full selection
```

详细报告为 `$CYCLE_ROOT/report.json`，三个阶段的控制台分别保存在
`phase1-train-interrupted.log`、`phase2-evaluation-only.log` 和
`phase3-training-resumed.log`。第一阶段非零退出是脚本主动制造的测试条件，
不是服务器故障；脚本只终止自己启动的独立进程组，不会停止 Docker 容器。

若 GPU 2/3 正被实验室其他任务占用，可以先在 GPU 0/1 上运行完全相同的恢复
闭环，只把参数改成 `--gpus 0,1`。此时仍使用 `num_generations=4`，每张卡顺序
生成两条候选，最终输出中的名称相应变为：

```text
PASS real 2-GPU train/evaluate/resume validation
```

这能验证 snapshot、评测队列、best selector 和训练恢复逻辑，但不改变正式主
训练仍使用 `--gpus 0,1,2,3` 的配置。

`lora_policy.py`、`rl_env.py`、奖励/状态/提示词或训练入口；它们已经进入 run

```text
--steps-per-generation

```

同一任务的 4 条候选。也没有添加 `--full-determinism`，因为它只用于逐字节
恢复验证，正式长训练会受到明显的性能影响。

### 若要挑选卡做训练

如果决定用 GPU 0/1 开始正式训练，只需把：

```bash
--mode ddp \
--gpus 0,1,2,3 \
--nccl-profile blackwell-safe
```

改为：

```bash
--mode ddp \
--gpus 0,1 \
--nccl-profile blackwell-safe
```

其余参数保持不变。`num_generations=4` 时，两张卡各顺序生成两条 rollout，仍然组成同一个四候选 GRPO group，只是速度会比四卡慢。

不同空闲卡数的规则如下：

| 空闲卡数 | 配置 | 是否推荐 |
|---|---|---|
| 1 张 | `--mode single --gpus N`，删除 `--nccl-profile blackwell-safe` | 可以，但较慢 |
| 2 张 | `--mode ddp --gpus N,M --nccl-profile blackwell-safe` | 可以 |
| 3 张 | 不能直接配合 `num_generations=4` | 选择其中两张 |
| 4 张 | 当前正式四卡命令 | 最快 |

三卡不能直接使用，是因为：

```text
num_generations % world_size == 0
```
world_size 是卡的数量，num_generations 是组内rollout的数量。

当前 `4 % 3 != 0`。虽然可以把 `num_generations` 改成 6，但这会改变 GRPO 组大小和实验配置，不建议为了利用第三张卡这样做。

还有一个非常重要的限制：同一个训练 run 启动后，GPU 数量不能改变。

例如：

```text
首次用 2 卡启动
→ 后续所有 checkpoint 恢复都必须用 2 卡
```

可以在相同型号的 GPU 之间更换物理编号，例如从 `0,1` 换成 `2,3`，但数量必须仍是 2；为了复现稳定，最好连编号顺序也保持一致。

## 5. 正式命令字段说明

### 5.1 启动层

| 字段 | 含义 |
| --- | --- |
| `--mode ddp` | 使用 `torchrun` 启动多进程 DistributedDataParallel |
| `--gpus 0,1,2,3` | 使用四张物理 GPU，同时决定 `nproc_per_node=4` |
| `--nccl-profile blackwell-safe` | 使用已经在当前 PCIe Blackwell 服务器验证过的安全 NCCL transport |
| `--` | 此前是 launcher 参数，此后全部转交 `train_grpo.py` |
| `--process-group-timeout-seconds 7200` | DDP collective 的有限超时。两卡各串行两条 rollout 时，极长 completion 可使 rank 相差超过 PyTorch NCCL 默认的 600 秒；正式配置使用 7200 秒，仍会对真正的长时间卡死报错 |

### 5.2 数据与环境

未显式给出的 annotation、action-plan cache、场景文本、connectivity、CLIP
cache、CLIP 模型和 Qwen 模型路径使用 `train_grpo.py` 中已经验证过的项目默认值。

| 字段 | 含义 |
| --- | --- |
| `expected-instruction-count=14039` | 防止误读不完整或错误的 train split |
| `clip-text-device=auto` | 每个 rank 在已经绑定的本地 GPU 上运行冻结 CLIP text tower |
| `clip-text-dtype=fp16` | CLIP 在线思维文本编码采用 FP16；缓存模型身份仍会严格校验 |
| `max-navigation-steps=10` | 每条导航 episode 最多 10 个环境动作 |
| `max-tool-calling-iterations=10` | TRL 最多允许 10 轮工具调用，与环境上限一致 |
| `navigation-progress-scale=5.0` | 连续距离势函数缩放；移动奖励为 `5 × (d_prev-d_cur)`，算法版本和数值进入 run manifest |
| `semantic-potential-scale=4.0` | `bounded_raw_visual_potential_v1` 的 source scale；新值必须先通过反事实扫描，理论 episode 绝对值不得超过成功奖励的 25% |
| `thought-reward-weight=0.25` | `grounded_auxiliary_v1` 的保守权重；文本子目标对齐为 0，环境可核验动作才有正奖，协议与权重进入 run manifest |

### 5.3 LoRA

| 字段 | 含义 |
| --- | --- |
| `r=16` | LoRA 低秩维度 |
| `lora-alpha=32` | LoRA 更新缩放系数 |
| `lora-dropout=0.05` | adapter 配置值；GRPO 中实际 dropout 被统一禁用 |
| `max-trainable-percentage=1.0` | 安全上限：可训练参数不得超过全模型 1%，防止主干意外解冻 |
| `dtype=bf16` | Qwen/LoRA 的训练计算精度 |

### 5.4 GRPO 与优化器

| 字段 | 含义 |
| --- | --- |
| `max-completion-length=8192` | 正式训练的单条 completion 硬件安全上限；Level 2 的 38912 仅为理论审计上界，不直接用于训练 |
| `num-generations=4` | 每个 task 采样 4 条 rollout 做组内比较 |
| `learning-rate=1e-6` | LoRA AdamW 学习率 |
| `weight-decay=0` | 不对 LoRA 施加额外权重衰减 |
| `warmup-ratio=0.03` | 前 3% optimizer steps 做学习率 warmup |
| `max-grad-norm=1.0` | 梯度范数超过 1 时裁剪 |
| `lr-scheduler-type=cosine` | warmup 后使用 cosine 学习率衰减 |
| `beta=0.001` | reference policy KL 约束强度 |
| `temperature=1.0` | rollout 采样温度，提供组内探索差异 |
| `top-p=0.95` | nucleus sampling 的累计概率阈值 |

### 5.5 训练长度、日志与保存

| 字段 | 含义 |
| --- | --- |
| `trainer-max-steps=2500/1500` | 四卡模板固定 2500 steps；两卡、两到三天预算参数组固定 1500 steps；正值优先于 epoch 上限 |
| `num-train-epochs=1.0` | Trainer 的 epoch 安全上限；当前命令通常先由固定 max steps 结束 |
| `logging-steps=1` | 每个 optimizer step 写一次聚合指标 |
| `save-steps=10` | 每 10 个 optimizer steps 保存一次完整 checkpoint，降低意外中断造成的进度损失 |
| `save-total-limit=3` | 只保留最近 3 个 checkpoint |
| `trajectory-log-interval=10` | 每 10 个 group 额外记录一次详细逐步轨迹 |
| `seed=0` | 当前首个正式训练随机种子 |

### 5.6 验证与 best 选择

| 字段 | 含义 |
| --- | --- |
| `validation` | 开启训练期标准 R2R 评测；未显式开启时不加载 Val-Unseen |
| `validation-fast-subset-size=128` | 固定快评样本数；ID 由 seed+instr_id 的 SHA256 一次性选定 |
| `validation-fast-interval-steps=1000/500` | 四卡模板每 1000 step 快评；两卡 1500-step 参数组每 500 step 快评 |
| `validation-max-new-tokens=256` | 每次导航 tool decision 最多生成 256 tokens；正式协议固定值 |
| `validation-seed=0` | 固定 subset 身份与贪心评测协议 |

快评和完整评测都使用贪心解码，不采样。候选顺序按 `SPL`、`SR`、`nDTW`、
更低 `NE`、更早 step 依次比较。`save-total-limit=3` 只清理 Trainer checkpoint；
每个待评候选会先原子复制为 `validation/snapshots/step-N`，其中只有三份 LoRA
推理文件和逐文件哈希，不会随旧 checkpoint 删除。`validation/queue.json` 记录
评测事件与 job 状态，`validation/state.json` 只保存 selector 的 quick/full best。

`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 用于降低动态生成长度造成的
显存碎片，但它不能解决真实分配量超过 96GB 的问题；8192 硬上限才是本次 OOM
的主要保护。`TOKENIZERS_PARALLELISM=false` 和 `OMP_NUM_THREADS=1` 用于避免
多个训练进程各自创建过多 CPU 线程。

```bash

"$TRAIN_PYTHON" - "$OUTPUT_DIR/logs/train_metrics.jsonl" <<'PY'

import pathlib
import sys

path = pathlib.Path(sys.argv[1])
rows = [json.loads(line) for line in path.read_text().splitlines() if line]
rows = rows[-100:]

print("completed_steps:", len(rows))
print(
    "max_observed_completion_length:",
    max((float(row.get("completions/max_length", 0)) for row in rows), default=0),
)
print(
    "max_clipped_ratio:",
    max((float(row.get("completions/clipped_ratio", 0)) for row in rows), default=0),
)
print(
    "mean_clipped_ratio:",
    (
        sum(float(row.get("completions/clipped_ratio", 0)) for row in rows)
        / len(rows)
        if rows
        else 0
    ),
)
PY
```

`completions/clipped_ratio=0` 表示该 step 的四条 completion 都在 8192 以内。
偶发的非零值说明硬上限成功截断了异常长输出，不等同于训练失败；若它在大量
连续 step 中持续非零，应暂停并检查详细 rollout，而不是在同一 run 中途修改
上限。所有正式主实验必须保持相同的 8192 配置。

若环境已经终止，而完整的最后一条 tool observation 只因零梯度尾部超出 8192，
runtime 会把它替换为仅含 termination reason 的紧凑 tool result。assistant tool
call、对应 tool result、最终 EOS、环境状态和 reward 全部保留，模型已生成 token
不被截断；rollout 记录 `terminal_tool_suffix_compacted` 及压缩前后 token 数，训练
指标记录 `nav/terminal_tool_suffix_compaction_rate`。若紧凑 result 仍无法放入，
则继续 fail-closed，绝不丢失 EOS 或制造孤立 tool call。

奖励族和分项会同时给出 mean/std、最小/最大值、非零率、正率和负率；当 smoke
run 使用 `--trajectory-log-interval 1` 时，还会汇总 Thought 动作判定状态、文本

扫描器会在 source scale 上逐条复现已记录 episode return，然后只线性重标定
`semantic/alignment_delta`，精确重算失败 `tanh` 整形、clean all-fail 的
final/minimum-distance 排序、endpoint success preference 和基于训练图轨迹的
endpoint-SPL surrogate。它是训练前安全与 attribution gate，不是“新 scale
必然产生相同 policy”的离线承诺。任何候选超过成功 terminal 25% 的理论上限
都会直接失败；选择时应取不破坏总 reward 对齐的最小有效放大值。

run manifest 会再次校验数据、模型、LoRA、优化参数、代码摘要和 world size。
任一不可变字段不一致都会拒绝续训，不要通过删除 manifest 绕过检查。
通用 checkpoint 恢复命令故意不传
`--validation-max-new-tokens`：恢复时程序会从原 run manifest 继承已封存值
（包括旧协议的 `512`）。只有新 run 启动模板才显式使用当前正式
`256` 协议；不要在恢复旧 run 时强行改成 `256`。

连续 progress shaping 是新的 reward 科学身份，不能从旧
`progress_reward=+5/positive-step` 实验的 checkpoint 接着训练。旧 adapter
仍可通过正式 native evaluator 评测，但新 reward smoke/正式训练必须使用新的
输出目录；run manifest 会拒绝把两种 reward 伪装成同一次 resume。

DDP 恢复启动时，日志中应先出现两类校验。以 `checkpoint-370` 为例，二者的
`sha256` 都应等于该 checkpoint 的 `navgpt_grpo_checkpoint.json` 中记录的
`trainable_parameter_sha256`：

```text
DDP LoRA-only boundary: ... resume_sync=True ... initial_sha256=<checkpoint SHA256>
DDP resume post-load LoRA sync: ... sha256=<checkpoint SHA256> reference_sha256=<64位摘要>
```

`resume_sync=True` 不是错误，它表示某个 worker rank 原本仍持有初始 LoRA，
程序已经从 rank 0 逐个小张量修复并通过逐字节校验。若日志中的 checkpoint
SHA256 不一致，程序会在生成第一条续训轨迹前停止，不能绕过该检查。

上面的 `--resume-implementation-patch-reason` 只用于从本次同步修复之前生成的
旧 checkpoint（例如当前 `checkpoint-370`）首次恢复。它不能放宽任何模型、
数据、奖励、超参数或 world size 检查；唯一允许的差异是实现代码摘要。授权会
写入 `navgpt_grpo_implementation_patches.json`，并复制进后续 checkpoint 和
最终 adapter。相同代码再次启动时可省略该参数；全新 run 不得添加该参数。

正常续训会自动先处理 `queue.json` 中未完成的评测，然后继续训练。如果只想先
完成评测、确认 best 状态而暂时不恢复 optimizer，在上述恢复命令的
`--resume-from-checkpoint "$CHECKPOINT"` 后再加一行 `--validation-only`。该命令
完成后会退出且不会产生新 checkpoint；确认队列全部 completed 后，再运行不带
`--validation-only` 的原恢复命令。

## 10. 单卡等价命令（不用于本次四卡主 run）

单卡算法流程与四卡相同，但四条 rollout 在 GPU 2 上串行生成，入口自动使用

## 11. 哪些参数可以调整

任何参数变化都必须创建新输出目录，不能从旧 run checkpoint 继续。

可以作为后续独立实验调整：

- `seed`：多随机种子；
- `learning-rate`：建议单独尝试，不要在一个 run 中途改变；
- `beta`：KL 强度；
- `r/lora-alpha`：LoRA 容量消融；
- `num-train-epochs` 或 `trainer-max-steps`：训练长度；
- `navigation-progress-scale`：默认 5.0；修改后必须创建独立输出目录并作为
  reward ablation 报告，不能中途改变。
- `semantic-potential-scale`：source 为 4.0；修改前必须运行
  `audit_semantic_reward_scaling.py`，并创建独立输出目录。代码会拒绝超过成功
  terminal 25% 理论上限的值。
- `thought-reward-weight`：第四阶段固定为 0.25；修改后同样必须创建独立输出
  目录。第三阶段 checkpoint 的 Thought 身份不同，不能恢复到第四阶段实验。

当前不要随意调整：

- `max_completion_length`：本次主实验固定为 8192；Level 2 的 38912 是理论审计
  上界，不是 96GB GPU 的安全训练值。改变上限必须创建新 run，且不能与本次
  主实验直接合并比较；
- `num_generations/steps_per_generation/gradient_accumulation_steps`：当前 DDP
  契约固定一个完整 group；
- `max_navigation_steps` 与 `max_tool_calling_iterations`：两者需要同步设计；
- `nccl-profile`：当前服务器四卡必须保留 `blackwell-safe`；
- `dtype`：当前验证和显存预算基于 BF16。

## 12. 冻结加载训练后的 adapter

统一推理加载契约已经实现。它会校验 adapter manifest、基础模型权重指纹、
LoRA 超参数和 48 层目标覆盖，然后使用 `is_trainable=False` 加载 PEFT，确认
所有参数的 `requires_grad=False`、模型处于 `eval()`，并运行一次短生成：

```bash
cd /workspace/RL-NavGPT/nav_src

TRAIN_PYTHON=/home/xl/venvs/navgpt-rl/bin/python
POLICY_MODEL=../models/Qwen2.5-14B-Instruct-1M

ADAPTER_PATH="/workspace/RL-NavGPT/outputs/$RUN_DIR_NAME/$FINAL_ADAPTER_NAME"

test -f "$ADAPTER_PATH/adapter_model.safetensors"
test -f "$ADAPTER_PATH/navgpt_adapter_manifest.json"

PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES=2 \
  "$TRAIN_PYTHON" scripts/validate_lora_policy.py inference \
    --model-path "$POLICY_MODEL" \

    --dtype bf16 \
    --max-new-tokens 8
```

最后必须输出：

```text

```

`NavGPT.py` 是历史 LangChain `<Think>/<Action>` 入口，不是正式 RL
evaluator。它默认拒绝 `--local_adapter_path`；只有为了历史复现才可
显式加 `--allow_legacy_adapter_evaluation`。这种运行的
`evaluator_manifest.json` 会固定标记
`evaluator_family=legacy_langchain` 与 `official_rl_comparable=false`，不得
作为 Base/LoRA 正式指标。

正式协议从本阶段起统一为每次 tool decision 最多 `256` 个新 token。
历史 `--validation-max-new-tokens 512` 的评测输出属于旧 token-budget
协议；即使它由 native evaluator 产生，也不得与新 256-token 结果
直接混合或覆盖。

## 13. 训练完成后还不能直接宣称 8.1 完成

冻结 adapter 加载、标准 R2R 指标和训练期 best 选择已经完成。直接
隔离 RL 收益的正式主对比只允许使用上述 native 入口：

训练期 `nav/success_rate` 只用于诊断，不能替代以上独立测试结果。
